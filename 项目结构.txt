数据库表（PostgreSQL）
====================

users               # 用户表（账号、密码哈希、角色、昵称）
knowledge_points    # 知识点表（科目、系统、名称、关键词）
questions           # 题目表（题干、选项、答案、解析、状态、版本）
experts             # 专家表（姓名、科室、职称、擅长知识点）
review_flows        # 审核流程配置表（流程名、轮次配置JSON）
review_tasks        # 审核任务表（题目ID、流程ID、当前轮次、状态）
review_records      # 审核记录表（任务ID、轮次、审核人、结论、意见）
question_versions   # 题目版本表（题目ID、版本号、JSON快照）
image_prompts       # 图片提示词表（题目ID、结构化提示词）
generated_images    # 候选图表（提示词ID、图片路径、审核状态）
image_review_records# 图片审核记录表


API 接口
========

认证:
  POST   /api/auth/login              登录（返回JWT）
  GET    /api/auth/me                 当前用户信息
  PUT    /api/auth/profile            修改昵称
  POST   /api/auth/change-password    修改密码

用户管理（仅管理员）:
  GET    /api/users                   用户列表
  POST   /api/users                   创建用户

题目:
  POST   /api/questions/generate      生成题目（调千问）
  GET    /api/questions               题目列表
  GET    /api/questions/search?q=     搜索题目
  GET    /api/questions/{id}          题目详情
  PUT    /api/questions/{id}          修改题目
  DELETE /api/questions/{id}          删除题目

知识点:
  GET    /api/knowledge-points        知识点列表（分页）
  GET    /api/knowledge-points/search 搜索知识点
  POST   /api/knowledge-points        创建知识点
  POST   /api/knowledge-points/import Excel导入
  DELETE /api/knowledge-points/{id}   删除知识点

专家:
  GET    /api/experts                 专家列表
  POST   /api/experts                 创建专家
  PUT    /api/experts/{id}            修改专家
  DELETE /api/experts/{id}            删除专家

图片:
  POST   /api/images/prompt           生成生图提示词
  POST   /api/images/generate         生成候选图
  GET    /api/images/{questionId}     候选图列表
  POST   /api/images/review           审核图片

审核:
  POST   /api/review/submit           提交审核
  POST   /api/review/action           审核操作
  GET    /api/review/task/{id}        审核任务详情
  GET    /api/review/task-by-question/{id}  按题目查审核任务
  GET    /api/review/records/{id}     审核记录
  GET    /api/review/flows            审核流程列表

统计:
  GET    /api/stats                   系统统计


角色权限
========

admin（管理员）:  全部权限
expert（专家）:   出题、知识点增删、题库删除、审核、专家查看
teacher（教师）:  出题、知识点查看、提交审核


从头了解项目的阅读顺序
========================

第一层：先看"是什么"
--------------------
1. 功能需求文档.txt         ← 产品要做什么，树状图是核心
2. CLAUDE.md                ← 开发约束，什么不能做
3. README.md                ← 项目简介


第二层：理解数据结构（domain）
----------------------------
4. internal/domain/types.go      ← 核心：题目、知识点、选项长什么样
5. internal/domain/validate.go   ← 题目校验规则
6. internal/domain/review.go     ← 审核相关的数据结构
7. internal/domain/image.go      ← 图片相关的数据结构

这层回答：系统里有哪些数据，字段是什么，状态怎么流转。


第三层：理解存储层（storage）
----------------------------
8.  internal/storage/memory.go           ← 题目怎么存（最简单的实现）
9.  internal/storage/knowledge_store.go  ← 知识点怎么存
10. internal/storage/review_store.go     ← 审核数据怎么存
11. internal/storage/image_store.go      ← 图片数据怎么存
12. internal/storage/postgres/schema.sql ← 数据库表结构（10张表的关系）
13. internal/storage/postgres/store.go   ← PostgreSQL 实现

这层回答：数据存在哪里，怎么增删改查。


第四层：理解业务逻辑（service）
------------------------------
14. internal/llm/client.go + qwen.go    ← 怎么调千问API
15. internal/generator/prompt.go         ← 怎么构建出题prompt
16. internal/generator/service.go        ← 出题流程
17. internal/evaluator/service.go        ← 质量评估规则
18. internal/knowledge/service.go        ← 知识点管理逻辑
19. internal/review/service.go           ← 审核流程逻辑（核心复杂度在这）
20. internal/image/service.go            ← 图片生成和审核逻辑

这层回答：每个功能具体怎么做，业务规则是什么。


第五层：理解流程编排（pipeline）
------------------------------
21. internal/pipeline/pipeline.go        ← 把上面的service串起来，对外暴露方法

这层回答：各个模块怎么协作，一个请求从进来到出去经过哪些步骤。


第六层：理解 API 层（api）
--------------------------
22. internal/api/server.go               ← 路由表：哪些URL对应哪些handler
23. internal/api/handler_auth.go         ← 登录、权限
24. internal/api/handler_question.go     ← 题目相关接口
25. internal/api/handler_review.go       ← 审核相关接口
26. internal/api/handler_utils.go        ← JSON读写、CORS

这层回答：前端调哪个URL，后端怎么处理。


第七层：理解入口和配置
--------------------
27. internal/config/config.go            ← 配置从哪来
28. internal/auth/auth.go                ← JWT怎么签发、权限怎么检查
29. cmd/aigo/main.go                     ← 程序从哪开始，怎么组装各模块
30. configs/review_flows.json            ← 审核流程怎么配置

这层回答：系统怎么启动，配置怎么管理。


第八层：理解前端（web）
----------------------
31. web/src/auth.js                      ← 前端怎么存token
32. web/src/api.js                       ← 前端怎么调后端
33. web/src/router.js                    ← 页面路由
34. web/src/App.vue                      ← 整体布局
35. web/src/pages/LoginPage.vue          ← 登录流程
36. web/src/pages/GeneratePage.vue       ← 出题页面
37. web/src/pages/ReviewPage.vue         ← 审核页面
38. web/src/pages/BankPage.vue           ← 题库页面

这层回答：用户看到什么界面，怎么和后端交互。


一句话总结每层
==============
domain    → 数据长什么样
storage   → 数据存在哪
service   → 业务怎么做
pipeline  → 流程怎么串
api       → 对外怎么调
config    → 系统怎么配
main.go   → 程序怎么跑
web/      → 用户怎么看
