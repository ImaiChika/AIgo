AIgo 当前还缺的功能提示
========================

说明：
本文件用于提示后续开发者当前项目和前端原型还缺哪些关键部分。
开发时请以根目录《功能需求文档.txt》和《CLAUDE.md》为准，不要主动扩展无关模块。


一、前后端连接
--------------

目前已有静态前端原型，但还没有真正接入 Go 后端 API。

还缺：
- Go HTTP 服务入口。
- 前端调用后端的 API 封装。
- 统一错误提示。
- 统一请求/响应 JSON 格式。
- 前端页面的真实数据加载。


二、知识点 Excel 导入
--------------------

当前项目已有知识点相关后端代码和 Excel 文件，但前端还没有接入完整导入流程。

还缺：
- 知识点 Excel 上传页面。
- 后端上传接口。
- Excel 解析结果预览。
- 导入前字段校验。
- 知识点版本记录。
- 知识点搜索接口。
- 前端知识点下拉框改成真实数据。


三、千问出题接口
----------------

当前前端的“AI 自动生成试题”还是模拟交互。

还缺：
- 后端生成试题 API。
- 调用千问 API 的真实流程。
- 生成请求参数组装：专业、难度、知识点、数量。
- 生成结果 JSON 解析。
- 生成失败时的错误处理。
- 生成任务记录：模型名、提示词、生成时间。
- 前端展示真实生成结果。


四、AI 生图与候选图管理
-----------------------

当前前端已经有“AI 配图候选”界面，但候选图是前端模拟 SVG，不是真实生图。

还缺：
- 生图模型接入。
- 结构化生图提示词生成接口。
- 每题生成 3-5 张候选图。
- 候选图保存路径或对象存储方案。
- 候选图状态：待审核、通过、驳回。
- 候选图与题目绑定。
- 专家选择最终配图。
- 生图失败时的重试或提示。

注意：
- AI 生成图片不能直接进入正式题库。
- 图片必须经过专家审核。
- 配图优先作为“医学教学示意图”，不要当真实诊断影像。


五、题目基础校验
----------------

当前已有部分校验逻辑，但还没有完整接到前端工作流。

还缺：
- 题干是否为空校验。
- 选项数量校验。
- 正确答案是否存在于选项中校验。
- 多个正确答案风险提示。
- 配图是否已审核校验。
- 校验结果在前端展示。

说明：
- 首期不强制校验解析。
- 首期不强制校验试题来源。


六、专家库
----------

功能需求中要求有专家库，但目前还没有完整前端和持久化管理。

还缺：
- 专家列表页面。
- 新增/启用/停用专家。
- 专家所属专业或科室。
- 专家擅长知识点。
- 专家可审核题型。
- 专家数据持久化。


七、多轮审核流程
----------------

老师明确要求：A2 出题可能存在多轮审核，审核几轮、每轮谁审核，都要后台配置。

还缺：
- 审核流程配置页面。
- 审核轮数配置。
- 每轮审核人或专家组配置。
- 每轮是否允许修改。
- 每轮通过条件。
- 题目提交审核后生成审核任务。
- 当前审核轮次展示。
- 审核通过、驳回、退回修改。
- 审核意见记录。
- 修改前后版本记录。


八、带图题审核
--------------

带图题需要题目和图片分别审核。

还缺：
- 图片审核入口。
- 图片审核意见。
- 图片通过/驳回状态。
- 题目审核状态和图片审核状态联动。
- 只有题目和图片都审核通过后才能入库。


九、题库管理
------------

当前还没有完整题库管理页面和持久化。

还缺：
- 题目列表。
- 按专业、知识点、难度、状态查询。
- 关键词搜索。
- 查看题目详情。
- 查看配图。
- 查看审核记录。
- 查看题目版本。
- 导出审核通过的题目。


十、数据持久化
--------------

当前有内存存储占位，但正式功能需要数据库。

还缺：
- 数据库选型确认。
- 数据表设计。
- 题目表。
- 知识点表。
- 知识点版本表。
- 专家表。
- 审核流程表。
- 审核任务表。
- 审核记录表。
- 图片候选表。
- 题目版本表。

建议：
- 原型可先用 SQLite。
- 正式版优先 PostgreSQL。


十一、前端页面还缺
------------------

当前只有 AI 出题工作台静态原型。

还缺页面：
- 知识点 Excel 导入页。
- 知识点搜索页。
- 专家库管理页。
- 审核流程配置页。
- 审核任务列表页。
- 题目审核详情页。
- 图片审核页。
- 题库查询与导出页。


十二、权限与安全
----------------

目前还没有用户登录和权限控制。

还缺：
- 登录。
- 用户角色。
- 管理员权限。
- 专家审核权限。
- API Key 安全配置。
- 操作日志。


十三、暂时不要做的内容
----------------------

当前不要实现：
- 知识图谱。
- Neo4j。
- 混淆网络。
- IRT 或深度 IRT。
- Bloom 分类。
- 强化学习优化。
- 医学模型微调。
- 复杂来源资料管理。
- 历史真题强依赖。
- 把解析或试题来源做成必填。

如果后续需要历史真题，只做轻量参考加载：
选择知识点 -> 检索少量相关样例 -> 加入提示词上下文 -> 千问参考生成新题。


十四、建议下一步开发顺序
------------------------

1. 先做 Go HTTP 服务和基础 API。
2. 接知识点 Excel 导入与搜索。
3. 接千问真实出题。
4. 接题目保存和查询。
5. 接 AI 生图候选图流程。
6. 做专家库。
7. 做多轮审核流程配置。
8. 做题目审核和图片审核。
9. 做题库导出。
10. 最后再补登录、权限和操作日志。
