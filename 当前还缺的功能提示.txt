AIgo 当前还缺的功能提示
========================

说明：
本文件用于提示当前项目还缺哪些关键部分。
开发时请以根目录《功能需求文档.txt》和《CLAUDE.md》为准。


已完成的功能
============

一、前后端连接 ✅
-----------------
- Go HTTP 服务（internal/api/，30+ 个 REST 接口）
- 前端 API 封装（web/src/api.js）
- 统一 JSON 格式和错误处理
- CORS 跨域支持
- 前端页面对接真实后端数据

二、知识点管理 ✅
-----------------
- 知识点 xlsx 导入
- 知识点搜索（按名称、关键词、系统）
- 前端知识点页面（搜索、添加、删除、Excel 导入）

三、千问出题 ✅
---------------
- 调用千问 API 生成 A2 型题（qwen3.5-flash）
- 结构化 JSON 输出 + 解析
- 前端出题页面（选知识点、生成、编辑、保存）
- 多题生成 + 左右切换查看

四、AI 质量检查 ✅
------------------
- LLM 检查题目质量（科学性、逻辑性、A2适配度、答案准确性）
- 四维评分（0-100）
- 问题列表 + 修改建议
- 检查通过自动更新状态为 ai_reviewed
- 结果持久化到数据库
- 支持批量检查
- LLM 可调换（通过 llm.Client 接口）

五、批量推理 ✅
---------------
- DashScope 批量 API，云端执行
- 任务提交、状态轮询、结果下载
- 任务历史持久化（PostgreSQL）
- 导入结果详情（成功/失败/原因）
- 前端批量推理页面

六、题目管理 ✅
---------------
- 题目 CRUD（创建、读取、更新、删除）
- 题目搜索（支持 ID、题干、答案）
- 前端题库页面（搜索、筛选、详情、编辑、删除）
- 导出 Excel (.xlsx)、Word (.docx)

七、专家库 ✅
-------------
- 专家 CRUD
- 前端专家库页面（增删改查、启用停用）
- 创建专家角色账号时自动同步到专家库

八、多轮审核 ✅
---------------
- 审核流程配置（JSON 文件 + 前端页面）
- 可配置轮数、每轮审核人、通过人数门槛
- 提交审核 → 多轮审核 → 审核通过/驳回
- admin 可审核任意轮次
- 审核记录留痕
- 前端审核页面（选题、提交、审核、查看记录）

九、题目发布 ✅
---------------
- 审核通过 → 管理员手动发布 → 正式题库
- 前端题库页面有发布按钮（仅管理员可见）

十、用户认证 ✅
---------------
- JWT 登录
- RBAC 三种角色：admin、expert、teacher
- 前端登录页面
- 侧边栏显示用户信息
- 用户可自定义昵称
- 前端路由守卫（未登录跳转登录页，非管理员禁止访问管理页面）
- JWT 密钥从环境变量读取

十一、操作日志 ✅
-----------------
- 记录题目增删改、审核、发布操作
- 前端日志页面（仅管理员可见）
- 支持按题目ID、按操作人筛选

十二、生图 ✅
-------------
- z-image-turbo 真实生图
- 生图提示词生成（调千问）
- 每题生成多张候选图
- 图片审核（通过/驳回）
- 图片绑定到题目

十三、数据库 ✅
---------------
- PostgreSQL 持久化存储
- 12 张数据表
- 启动时自动建表

十四、一键启停 ✅
-----------------
- start.sh 一键启动（PostgreSQL + 后端 + 前端）
- end.sh 一键停止全部服务


还缺的功能
==========

一、知识点版本管理
-----------------
- 当前知识点导入后无法查看历史版本
- 需要记录每次导入的时间和数量

二、图片审核页面完善
--------------------
- 后端 API 已有，前端基础页面已有
- 需要：更完善的候选图对比、批量审核


暂时不要做的内容
================

- 知识图谱
- Neo4j
- 混淆网络
- IRT 或深度 IRT
- Bloom 分类
- 强化学习优化
- 医学模型微调
- 复杂来源资料管理
- 历史真题强依赖
- 把解析或试题来源做成必填
