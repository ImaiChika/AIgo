# AIgo 工业化使用差距分析

> 更新：2026-09-13。本文以根目录《功能需求文档.txt》为产品基准，并结合当前代码、真实 PostgreSQL 集成测试、隔离数据库 E2E 和导出专项回归整理。
>
> 本轮范围按用户要求收口：不讨论服务器、网站入口、端口、HTTPS、SSH、备份等部署事项；AI 生图、题目图片和多模态素材永久移出项目范围；批量推理暂缓，不列入近期开发计划；不保留只影响代码洁癖的低价值细项。

## 一、当前判断

AIgo 已从功能原型进入“核心流程完整、可持续试用”的阶段。年度大纲、AI 单题生成、首次 AI 质量检查、多轮审核、待我修改、个人/全局三层题库、分享审批、导出、RBAC、审计和任务恢复主链路均已形成，当前综合成熟度约为 **8/10**。

目前剩余问题主要是测试深度和质量治理增量，不再是基础流程无法运行或审核状态容易被并发破坏。

## 二、已完成且不再列为差距

- 题目唯一来源为 AI 生成；生成结果先进入 `ai_draft`，首次 AI 检查通过后进入 `ai_reviewed`，不能绕过人工审核进入正式题库。
- AI 检查任务具备持久化队列、抢占、租约、超时、重试、耗尽状态和服务重启恢复；检查结果、题目状态/淘汰档案、题目删除和任务完成已纳入同一 PostgreSQL 事务。
- 单题生成已升级为持久任务：请求快照落库后立即返回 `pending`，worker 负责租约、有限重试和重启接管；生成页面可按 `run_id` 刷新恢复，不再用长 HTTP 请求承载核心执行。
- 审核送审、投票、最终决断、退修重提、流程撤销、发布、归档和关键配置操作使用事务与并发锁；任务绑定题目版本，驳回终态锁定，需修改只回原生成者，最终成功终态统一为 `published`（界面显示“已通过”）。
- 三类审核个人待办已由 PostgreSQL 预过滤并批量装载，保留已投票移开、任务名单、出题人归属和评语隔离语义。
- 年度大纲版本、Excel/CSV/Word 多文件导入、目录树、单条知识点维护、整套软删除与版本回退、知识点快照已实现。
- 个人题库与全局题库、正式/待审核/淘汰三层逻辑视图、个人正式题分享审批和题库范围权限已实现。
- AI 服务配置支持超级管理员维护、生成/检查模型分离、API Key 加密落库和运行时切换。
- 题目主列表、统一搜索、审核结果、统计和知识点快照缓存已完成数据库/服务层优化；Word 导出使用原生 OOXML，不依赖 pandoc。
- Excel/Word 仅导出 `published` 题目，列固定为题号、题干、A-E、答案、说明、大纲代码、难度、认知、考核要点、专业、系统，**不再输出“命题人”列或“朝阳医院AI”占位符**。
- 归档删除、关键配置审计与业务写入已纳入同一事务；生成/检查 worker 和 API 路径已使用结构化 `slog` 记录运行上下文。
- 已建立 GitHub Actions：Go 全量/真实 PostgreSQL/竞态/漏洞扫描，前端安装、审计、状态测试和生产构建。
- 已完成一次 ECS 真实业务链路 UAT：仅生成 1 道题，临时审核账号完成 10 轮审核与最终决断，结果页/统计/日志/分享审批/全局正式题库均走通，测试数据已精确清理。
- 前端响应式复核已覆盖桌面与 390px 移动端 13 个核心页面；流程、审核结果、统计、日志、用户管理等页面已改为窄屏可读布局，不再要求横向拖拽，题库搜索/批量操作/分页仍可见。

- 隔离数据库 API 回归：注册最低权限、管理员授权、禁用即时失效、25 个权限点、知识点版本生命周期、分享审批、统计、审计、AI 配置权限共 32/32。

## 四、仍值得投入的 P1

### 1. 自动化测试覆盖深度

CI 已建立，核心 E2E 已固化，但 API、认证和部分 PostgreSQL 实现的语句覆盖仍偏低；E2E 目前需要 Chrome runner，尚未成为每次 CI 的必跑项。

**建议：** 将四个 Playwright 脚本接入可选 CI job，继续提高权限矩阵、异常输入、导入失败和导出边界的覆盖；保持测试数据自动隔离和清理。

### 2. 质量治理增量

当前已有规则校验和首次 AI 检查，但还没有固定医学 A2 基准集、模型/prompt 版本对比和重复题提示。

**建议：** 先建立小型人工确认基准集，记录模型、prompt 版本、通过率和专家退回原因；重复题检测先做提示，不直接自动删除题目。

### 3. 轻量业务协作

审核任务已经能可靠分配和恢复，但没有站内提醒、超时提示和工作量视图。

**建议：** 仅根据真实专家试用反馈增加轻量提醒，不提前引入复杂消息中心或自由 workflow。

## 五、明确边界

- **AI 生图永久退出当前项目范围**：不再实现、验收或排期题目图片、多模态素材、生图和图片审核。
- **批量推理暂缓**：现有模拟页面和兼容代码保留，本阶段不开发真实批量执行器，也不将其作为完成度或验收门槛。
- 不扩展知识图谱、Neo4j、IRT、Bloom、强化学习、医学模型微调和复杂来源资料管理。
- 当前按“单机构独立部署、机构内多用户”设计，不提前扩展共享数据库多租户平台。

## 六、建议实施顺序

1. 把现有 Playwright E2E 接入 CI 可选任务，继续补核心 API/存储覆盖。
2. 建立固定医学 A2 质量基准集和 prompt/模型回归记录。
3. 根据真实审核人员反馈增加轻量提醒和工作量统计。
4. 核心质量治理稳定后，再评估相似题提示和其他业务增量。

## 七、最终判断

当前版本适合自有客户展示、内部流程验证和小规模受控试用。核心审核一致性、持久任务、题库分层、导出和权限边界已经具备稳定基础；完成测试覆盖深度与质量基准后，再扩大真实用户范围更稳妥。
