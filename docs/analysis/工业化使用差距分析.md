# AIgo 工业化使用差距分析

> 更新：2026-09-12（第二轮）。本文以根目录《功能需求文档.txt》为产品基准，并结合代码审阅和回归测试整理。
>
> 本轮范围按用户要求收口：不讨论服务器、网站入口、端口、HTTPS、SSH、备份等部署事项；AI 生图已永久移出项目范围；批量推理暂缓，不列入近期优化计划；不保留只影响代码洁癖、不影响真实业务的细项。
>
> **2026-09-12 第二轮进展**：原 P0 两项（依赖安全升级、AI 检查事务化）与 P1 中的持续集成入口已经完成并全量回归，见第三节；P1 其余项保持不变。当前部署阶段：项目尚未验收，实时推理使用用户自有云端千问 API；客户本地部署为最终目标（资源未具备，接口已预留）。

## 一、当前判断

AIgo 已经从功能原型进入“核心流程完整、可持续试用”的阶段。年度大纲、AI 单题生成、首次 AI 质量检查、多轮审核、待我修改、个人/全局三层题库、分享审批、导出、RBAC 和审计主链路均已形成，本轮完成依赖升级与 AI 检查事务化后，当前综合成熟度约为 **8/10**。

剩余的主要差距集中在：单题生成还不是真正的持久任务、三类审核个人待办仍为内存分页、题目删除缺少归档留痕策略，以及结构化日志/指标尚未统一。

## 二、已经完成且不再列为差距

- 题目唯一来源已收口为 AI 生成；生成结果先保存为草稿，首次 AI 检查通过后进入 `ai_reviewed`，不能绕过人工审核进入正式题库。
- AI 检查已经具备持久化任务、抢占、租约、超时、指数退避、重试耗尽和服务重启恢复；人工修改不会再次触发 AI 检查。
- 审核结果语义已经拆清：需修改回到生成者的「待我修改」，驳回为终态锁定，通过后进入 `published`；已通过题目只能由管理员撤回后修订。
- 多轮审核、最终决断、流程撤销、退修重提和发布已经使用 PostgreSQL 事务与跨进程锁，审核任务绑定题目版本，避免并发丢票、重复提交和审核旧版本。
- 年度大纲版本、Excel/CSV/Word 多文件导入、目录树、单条增删改、整套删除、版本回退、知识点快照及任务提交时快照已实现。
- 个人题库与全局题库已经分离；正式、待审核、淘汰三个逻辑分层由题目状态唯一推导，个人正式题可申请分享到全局库并由管理员审批。
- 唯一超级管理员、可下放管理员、角色模板、直接权限、分类子题库范围和默认低权限注册已形成明确边界。
- 题目主列表、统一搜索、审核结果和统计的主要过滤/分页已下推 PostgreSQL；旧报告中“全部列表都在内存分页”的结论已经过时。
- Word 导出已改为原生 OOXML，不再依赖 pandoc；Excel/Word 仅允许导出 `published` 题目。
- AI 服务配置已经支持超级管理员维护、生成/检查模型分离、API Key 加密落库和运行时动态切换。
- 单题生成已有 `generation_runs` 运行记录和客户端幂等 ID，刷新后可以恢复当前执行状态和已生成结果。
- 当前回归结果：188 个 Go 测试通过，关键 API/认证/AI 检查/审核/PostgreSQL 包竞态测试通过，`go vet ./...`、`go build ./...`、前端生产构建和 7 个前端状态/导航测试通过。

## 三、原 P0：已于 2026-09-12 完成

### 1. 依赖安全升级 ✅

- Go 工具链固定到 `toolchain go1.26.8`（go.mod），Dockerfile 基础镜像固定 `golang:1.26.8-alpine` digest；excelize 升至 v2.11.0，`golang.org/x/crypto、x/net、x/text` 同步升级。
- 前端 `npm audit fix` 清除 PostCSS 与 nanoid 高危告警，`npm audit --audit-level=high` 通过。
- `govulncheck ./...` 复扫：**可达漏洞 0**（升级前 Go 1.26.1 标准库与 excelize 均有可达漏洞；剩余 1 条模块级告警为未被调用的 `x/crypto/openpgp`，无修复版本）。
- 全量 `go build`、`go vet`、`go test -race ./...`（含真实 PostgreSQL 集成测试）、前端构建、前端状态测试与三种知识点导入/Excel 导出依赖路径均回归通过。

### 2. AI 检查落库事务化 ✅

- 新增 `storage.AICheckOutcome` 与可选接口 `AICheckOutcomeStore`（`internal/storage/interfaces.go`）：检查结果、题目状态推进或“淘汰档案+删除题目”、检查任务完成收敛为**单个 PostgreSQL 事务**（`postgres.Store.ApplyAICheckOutcome`）。
- AI 检查服务改为统一 `applyCheckOutcome` 入口：worker 路径把任务完成与结论放进同一事务；旧实现中“通过结果已保存但题目状态更新失败只记日志”的缺陷已消除——任何一步失败整体回滚，任务回退由重试机制接管。
- 测试：5 个编排级测试（通过推进、淘汰删除、逐步故障注入原子回滚、人工流程状态不被改动）+ 4 个真实 PostgreSQL 集成测试（含版本冲突回滚、淘汰档案主键冲突回滚）全部通过；竞态测试通过。
- 行为说明：`ai_check_tasks` 与 `ai_review_results` 对题目本就级联删除，淘汰路径下任务行随题目清理、仅淘汰档案留档，与既有产品语义一致。

### 3. 持续集成入口 ✅

- 新增 `.github/workflows/ci.yml`：Go 全量测试（含 `AIGO_TEST_POSTGRES_DSN` 真实 PostgreSQL 集成测试）、存储/检查/审核包竞态测试、`govulncheck` 可达漏洞门禁；前端 `npm ci`、`npm audit --audit-level=high`、`node --test` 状态测试与生产构建。

### 4. 知识点接口提速（2026-09-12 晚追加完成）✅

- 诊断确认：知识点列表/目录树/元数据每个请求都全量装载整版知识点（生产 7207 条约 110–150ms），是公网访问“知识点加载有延迟”的主因。
- 修复：`knowledge.Service` 每版本快照缓存（预排序、服务层写入即失效、2 分钟 TTL 兜底进程外变更），列表/树/元数据/统计共用；筛选与排序语义、API 形状不变，前端零改动。热请求降至 10ms 量级，附 4 个缓存行为测试并通过竞态测试。
- 剩余关联项：三类审核个人待办的 SQL 分页仍按原计划推进（见下）。

## 四、P1：近期值得投入的生产能力

### 1. 单题生成仍需改成真正的持久任务

`generation_runs` 已解决刷新恢复和同一运行 ID 幂等，但模型调用仍在原 HTTP handler 中执行。应用进程在生成期间退出后，任务不能由新进程继续处理，只能在超时后被标记失败；运行记录也没有保存完整请求快照、模型、prompt 版本、尝试次数和失败阶段。

**建议：** 复用 AI 检查队列已经验证过的“pending/running + lease + retry”模式，先持久化生成请求和知识点快照，再由 worker 执行。响应返回任务 ID，页面轮询任务；保存题目、分类归属、运行结果和审计记录要定义清晰的事务边界。

### 2. 审核个人待办仍需数据库端分页

题目主列表与审核结果已经改为 SQL 分页，但「待我审核」「待我决断」「待我修改」仍会加载全部题目和任务后在 Go 内存中组合。小规模数据可用，任务持续积累后会增加延迟和内存占用。

**建议：** 为三类个人待办设计明确的查询接口和索引，按当前用户、任务状态、当前轮次、更新时间直接分页，并保持现有任务可见性和评语隔离语义。

### 3. 审计与删除需要形成可追溯策略

审核主记录已经可靠留存，但题目删除仍是物理删除，关联题目版本和审核记录会随外键级联删除；不少配置与批量操作的审计写入仍是 best-effort，失败不会阻止业务提交。

**建议：** 正式题与有审核历史的题目采用归档/逻辑删除；必须物理删除时保存不可变删除摘要和审批理由。关键权限、审核流程、正式题撤回/删除等操作应把业务写入和审计写入放入同一事务。

### 4. 自动化质量门槛：CI 入口已建立，覆盖深度仍待补强 ✅部分

持续集成入口已建立（见第三节第 3 条）：GitHub Actions 自动执行 Go 全量测试、真实 PostgreSQL 集成测试、竞态测试、依赖漏洞扫描、前端状态测试与生产构建，不再依赖人工记得跑全量回归。

剩余差距：API、认证和 PostgreSQL 实现的语句覆盖仍偏低；当前依赖 `/tmp` 的关键浏览器流程（注册→授权→建库→送审→投票→决断）还不是仓库内可重复脚本。

**建议：** 把浏览器流程脚本固化进仓库并纳入 CI 可选任务；逐步补充核心路径的语句覆盖。

### 5. 运行记录和可观测性需要统一

应用仍大量使用 `fmt.Printf`，没有统一事件字段、请求 ID 和关键任务指标。AI 调用出现超时、检查积压或状态不一致时，需要人工拼接多处日志才能还原过程。

**建议：** 使用 Go 标准库 `slog` 统一结构化日志；为单题生成和 AI 检查记录 run/task/attempt、用户、题目版本、模型、耗时和失败阶段，并暴露最少量的任务积压、成功率和耗时指标。

## 五、P2：核心稳定后再补

- 建立固定的医学 A2 题质量回归集，用于比较模型、prompt 和 AI 检查规则变化，避免升级后质量无依据地波动。
- 增加重复题/高度相似题提示，优先作为生成后和正式入库前的人工参考，不直接自动删除题目。
- 根据真实专家试用反馈决定是否增加站内任务提醒和审核超时提示，不提前建设复杂消息中心。
- 清理已经没有入口的遗留权限和历史文档描述，例如 `question:create`，避免管理员看到无法产生实际效果的配置项。

## 六、明确边界

- **AI 生图永久退出当前项目范围**：不再实现、验收或排期题目图片、多模态素材、生图和图片审核。
- **批量推理暂缓**：现有模拟页面和兼容代码可以保留，但本阶段不继续开发真实批量执行器，也不把它计入当前差距优先级。
- 不扩展知识图谱、Neo4j、IRT、Bloom、强化学习、医学模型微调和复杂来源资料管理。
- 当前仍按“单机构独立部署、机构内多用户”设计，不提前扩展共享数据库多租户平台。

## 八、最终判断

当前版本适合自有客户展示、内部流程验证和小规模受控试用。依赖升级与 AI 检查事务化完成后，核心业务的数据一致性风险已消除，持续集成保证了后续改动不致静默破坏旧流程；完成持久生成任务、结构化日志和待办分页后，系统才真正具备长期持续迭代与更高并发试用的工程基础。
