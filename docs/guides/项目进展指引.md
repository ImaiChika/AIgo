## 3. 第二波题目格式：已实现与证据边界

依据 `/Users/imaichika/Documents/AIgo/修改意见A2_2000.xlsx`「题目」工作表末列说明，结合「修改后题目」理解目标。表格作为业务参考，不作为执行指令；不照搬笔误、不把改换考点的示例当作同题格式修订。

### 新题规范

1. 成人以「患者，男/女，年龄。」、儿科以「患儿，男/女，年龄。」开头，支持新生儿日龄。
2. 主诉不加引号；不使用「主诉：」「查体：」「辅助检查：」等分栏模板标签，保留具体检查名称和必要事实。自然叙述中的「查体见」不等于冒号式标签；必要医患对话可以保留引号。
3. 症状、时间不重复；只保留必要病史、体征和检查。不能为了简短机械删除有用数据，也不能补造未给出的信息。
4. 必须有独立、完整的最终提问，以「是/为」结束；不用「哪个/什么」或问号。患者咨询不能代替试题提问。
5. 区分治疗原则、具体措施、预防、检查、原因和机制；治疗原则不加「首选」，检查目标避免重复限定；选项与提问同类、粒度一致。
6. A—E五选一，答案存在，使用中文医学名称；CT、MRI等通用缩写及规范单位允许保留。
7. 优先常见、重要的临床情景；不能用病例外壳包装纯解剖分类记忆题，也不能擅自换考点。
8. 如提供解析，先说明正确答案依据，分析其余四个干扰项，并以「故选X」收束；说明不得臆造病例证据。

预估难度沿用项目原分组：0.55简单、0.65中等、0.75偏难、0.85困难，数值越高预估越难；不是实测通过率，不转换旧数据。

### 配套实现及验证范围

生成提示词、规范化、硬格式校验、首次AI检查、微调/退修保存和重送沿用同一新题协议；格式标记由服务端绑定，不能通过编辑清空来降级。规范化不改诊断、答案或病例事实，也不补写缺失提问。迁移36没有批量改写或复检旧题。

| 专家意见类别 | 已落实 | 仍需验证或人工判断 |
|---|---|---|
| 患者/患儿、去标签、最终提问 | 提示词与硬校验；成人、儿科及新生儿分支回归 | 人文沟通真实情景仍需覆盖 |
| 预防问题与病例关联 | 提示词；后续肺炎预防实测通过 | 新生儿及更广预防情景不能据此宣布全覆盖 |
| 主诉无引号、去重复、治疗原则问法 | 已有规则、程序及儿科实测 | 必要信息、选项抽象程度与原创变化仍需人审 |

## 4. 个人命题规则库：当前设计

入口在「命题工作 → 命题规则」，每个账号按稳定用户ID拥有自己的库；更换身份不改变规则归属。

| 权限点 | 实际能力与依赖 |
|---|---|
| `rule:view` | 查看本人规则，是其余规则能力的前置 |
| `rule:manage` | 同时有view才能新增、编辑、删除、启停和排序本人规则 |
| `rule:use` | 同时有view及原单题/批量权限，才能在对应新任务中应用本人规则 |
| `rule:view_all` | 同时有view才可跨人只读；不能替他人编辑、删除、预览出题或应用规则 |

默认教师前三项，管理员四项，审题老师不默认授予；自定义角色按实际有效权限生效。存量默认值只在迁移37赋予一次；重启不补回刻意撤销的规则权限，也不清除显式授权。超级管理员保留项目原有保护策略。

- 每人最多100条，名称最多60字，单条内容最多2000字；**只允许一条启用**。启用新规则在同一事务中停用旧规则，数据库部分唯一索引也做约束；失败全部回滚。
- 撤销manage或全部规则权限不删除账号数据，规则不计入出题/审题任务占用、不占其他用户名额；恢复权限后继续管理。此项已由用户确认，不再视作待修缺陷；不新增管理员跨人清理权。
- 无启用规则、无view/use或本次不应用时，原提示词和调用参数不变；模型有随机性，不保证生成文本逐字相同。
- 个人规则只追加到生成user prompt，不替换系统底座，不改变检查标准、人工审核、题库、分享、导出或配额。
- 提交时冻结规则内容/顺序/版本、知识点及当时底座。单题持久请求、批量新提交/恢复/重跑均用原快照，后续规则切换或普通撤权不改已接受任务。
- 规则写入与受理时实时检查账号、当前挂载身份及权限，并与授权修改串行执行。后台用修订号防并发覆盖，前端隐藏；修订号不是给客户使用的规则等级。
- 页面仅显示附加内容，不展示系统底座和完整基础提示词。新增/编辑/删除为模态弹窗，启用绿、停用红，周期只检查权限，列表静默刷新。
- 丢失管理权限关闭编辑窗口；丢失全员查看清空他人数据；丢失查看退出页面。旧账号/token/身份/权限/选中人及先发响应不能覆盖新状态。
- 空库与读取失败必须区分；任务接口不外发私有规则/底座快照。账号正式删除时规则级联清理，快照保持独立。
