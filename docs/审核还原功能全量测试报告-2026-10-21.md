## 三、核心还原闭环（真实API题，浏览器操作）

用真实千问 API 生成 2 道 A2 题（急性下壁心梗、急性心包炎），走完整生命周期：

1. **轮审中还原**：心梗题送 F2 → e1 填未提交意见、e2 投通过 → 管理员还原 →
   - 心梗题回到作者"新题修改与送审"（角标 1→2，5 秒内自动收敛）；版本 v1 不变、review_revision 0→1；
   - e1 待办消失并提示"任务已被还原…已保留未提交评语"，未提交意见原文保留、提交按钮禁用；
   - 数据库：任务 0、意见 0、内容版本 1、AI 结果/首检任务各 1 不变；日志只剩 `create` + `review_restore`（旧 submit/review 删除）；
   - 统计：作者"我已出题"不变、新题+1；e1 待审-1；e2"我已审核"1→0。
2. **旧请求拦截**：同内容版本旧送审重放 409；已删任务迟到投票 404（明确提示可能已被还原）。
3. **换流程重审至终态**：还原题改送 F3 → 三轮全过 → 把关人浏览器决断通过 → published 入正式题库；事后日志链完整（review_restore 保留为新历史起点）。
4. **第三轮中途还原**：前两轮 6 票 + 第三轮 1 票 → 详情正确显示"7 条记录"，确认框准确报"清除 1 个送审批次、7 条意见、8 条旧审核日志"，还原后全部清零。
5. **待决断还原**：三轮 9 票全过后还原 → 把关人打开的决断页在 7.8 秒内收敛，未提交决断意见保留、提交禁用、9 条意见+10 条旧日志清除。

## 七、测试中出现的"疑似问题"与排查结论（均非产品缺陷）

1. **"撤权返回 200 未被拦截"**：我最初只把直授权限清空，但专家的 review:do 来自 expert 角色模板，直授清空不移除角色权限（正确行为）。改为降级角色后守卫正常 409。
2. **"还原偶发 409"**：我的脚本把预览响应字段 `token` 误取为 `preview_token`（得到 null），产品按设计对无效凭证返回 409"审核状态已变化"。用正确字段后同流程立即 200。该错误信息对"凭证无效/过期/篡改"统一表述，稍欠精确但不泄露内部状态，符合接口设计。
3. **"移动端横向溢出"**：仅在视口切换/布局中途瞬时测得，等待布局稳定后 scrollWidth=390=innerWidth、无超宽元素；正式 E2E 的移动断言也通过。

另有两点环境/体验观察（非缺陷）：
- **env 引导持久化**：首次以真实云配置启动时系统会把 env 引导为数据库活动配置（`qwen-env-bootstrap`），此后仅改环境变量不生效，需改数据库活动配置。本次因此意外用真实 API 多生成 4 题（已计费，见第八节）。属文档化行为，但部署/测试切换模型时需注意操作数据库活动配置。
- **还原页"全选本页"复选框无 aria-label**（行内选择框有）。不影响功能与自动化，属可访问性小改进建议。

## 十、控制组（既有功能无回归）

- 生成链路：真实/假模型出题、异步首检、首检通过入待审核层正常。
- 格式门禁：不合规题干修改被拒（"题干末尾必须有完整、明确的提问…"），门禁未因还原功能放松。
- 导出：published 题 Excel 导出 200；过程题导出 400"没有可导出的题目"。
- 正式题撤回（unpublish）：R1 撤回 → 回作者"待我修改" → 保存 v2 → `resubmit-revisions` 换 F1 重送（attempt=2、previous_task_id 血缘）→ 再审通过 → 再次 published（v2），与还原功能互不干扰。
- 题干/选项/解析内容、`question_versions`、AI 结果、首检任务在所有还原前后逐行不变（SQL 指纹级核对）。
