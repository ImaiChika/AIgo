## 1. 项目目的

构建一套面向国家执业医师考试 A2 型试题的 AI 智能命题系统，实现“知识点导入、AI 出题、质量初评、多轮专家审核、题库入库”的基本流程。

当前版本以直接调用千问大模型出题为主，不引入知识图谱，不强制使用历史真题，不把解析和试题来源作为首期必填内容。

大致流程：

```text
知识点 Excel / 多模态素材
        ↓
千问生成 A2 试题草稿
        ↓
基础质量初评
        ↓
多轮专家审核（后台配置审核几轮、每轮谁审核）
        ↓
修改、通过、驳回或重新生成
        ↓
正式题库
```

树状图梳理：

```text
智能命题系统
├─ 1. 基础数据
│  ├─ 知识点 Excel 批量导入
│  ├─ 知识点版本管理
│  ├─ 知识点搜索
│  └─ 多模态素材管理
│
├─ 2. AI 出题
│  ├─ A2 文本试题生成
│  ├─ 批量生成
│  ├─ 干扰项生成
│  └─ 多模态配图题生成
│
├─ 3. 质量控制
│  ├─ 基础格式校验
│  ├─ 答案唯一性校验
│  └─ 多模态素材风险提示
│
├─ 4. 多轮审核
│  ├─ 专家库
│  ├─ 审核流程配置
│  ├─ 每轮审核人配置
│  ├─ 审核意见与修改记录
│  └─ 最终入库
│
├─ 5. 题库管理
│  ├─ 题目查询
│  ├─ 状态管理
│  └─ 导出
│
└─ 6. 后续可选
   └─ 历史真题参考加载（如后续需要）
```

## 2. 项目范围

### 2.1 当前优先开发范围

- Go/Python 后端框架。
- 千问大模型 API 调用封装。
- A2 型试题格式生成。
- 知识点 Excel 批量导入。
- 知识点版本管理与搜索。
- 文本试题生成。
- 多模态配图题生成。
- 基础质量校验。
- 专家库。
- 可配置多轮审核。
- 题库查询与导出。

### 2.2 当前暂不考虑

- 知识图谱。
- Neo4j。
- 复杂来源资料管理。
- 历史真题强依赖。
- 解析和试题来源必填。
- IRT、Bloom、强化学习等研究模块。

### 2.3 历史真题的处理原则

当前不需要考虑历史真题。

如果后续确实要使用历史真题，不做复杂题库知识图谱，只做成类似 agent 的参考加载方式：

```text
用户选择知识点
        ↓
系统检索少量相关历史真题或样例
        ↓
把这些样例加载到提示词上下文
        ↓
千问参考样例生成新题
```

历史真题只作为提示词参考，不作为当前核心功能。

## 3. 用户角色

### 3.1 系统管理员

- 管理用户、角色和权限。
- 配置千问 API、数据库、生图模型等参数。
- 配置专家库。
- 配置审核流程、审核轮数和每轮审核人。

### 3.2 命题教师或医学专家

- 选择专业、知识点、难度和生成数量。
- 查看 AI 生成试题。
- 修改题干、选项和答案。
- 审核多模态配图是否可用。
- 填写审核意见。
- 决定通过、驳回或要求修改。

## 4. 功能需求

### 01 试题领域模型

系统应定义统一的 A2 型试题结构。

首期核心字段：

- 题目 ID。
- 临床情境题干。
- 选项列表。
- 正确答案。
- 关联知识点。
- 难度等级。
- 多模态素材引用。
- 创建时间。
- 审核状态。
- 版本记录。

可选字段：

- 答案解析。
- 试题来源。

说明：

- 解析和试题来源首期不作为必填项。
- 后续如果老师要求再补充解析和来源，可作为扩展字段启用。

标准：

- 题目必须具备题干、选项和答案。
- A2 单选题默认支持 A-E 五个选项，必要时可兼容四选项。
- 答案必须存在于选项中。

### 02 知识点管理

知识点管理首期保持简单。

功能包括：

- 支持 Excel 批量导入知识点。
- 支持知识点版本管理。
- 支持按专业、科目、章节、关键词搜索知识点。

不做：

- 不做复杂单个知识点新增、编辑、删除流程。
- 不做知识点和诊疗指南、教材、文献的复杂关联。
- 不做知识图谱关系维护。

### 03 AI 文本试题生成

根据结构化请求调用千问大模型生成 A2 型试题。

输入参数：

- 专业或科目。
- 难度。
- 知识点。
- 生成数量。
- 可选临床场景。
- 可选多模态素材描述。

输出内容：

- 临床情境题干。
- A-E 选项。
- 正确答案。
- 难度。
- 关联知识点。

可选输出：

- 解析。
- 试题来源。

标准：

- 输出尽量使用严格 JSON。
- AI 生成结果默认为草稿，不能直接进入正式题库。
- 每次生成应记录模型名称、提示词和生成时间。

### 04 批量生成

功能包括：

- 根据同一知识点批量生成多道题。
- 批量生成失败时不影响已成功生成的题目。
- 每次批量任务记录模型、提示词和生成数量。

### 05 干扰项生成

功能包括：

- 围绕相近疾病、症状、检查、治疗方案生成干扰项。
- 避免明显错误或过于简单的选项。
- 避免多个正确答案。

当前不使用知识图谱或混淆网络，先由千问结合提示词直接生成。

### 06 多模态配图题生成

当前要求：必须支持 AI 生图，但要降低医学误差。

处理原则：

- 先生成文本题，再为题目生成配图。
- 配图优先定位为“医学教学示意图”，不是正式诊断影像。
- 生图必须使用结构化提示词。
- 每题生成 3-5 张候选图。
- 专家审核通过后，图片才能绑定正式题目。

生图提示词应包含：

- 图片用途。
- 图片类型。
- 医学主题。
- 必须出现的要素。
- 禁止出现的要素。
- 风格要求。
- 对应知识点。
- 审核重点。

示例：

```text
图片用途：执业医师考试 A2 型题配图
图片类型：医学教学示意图
医学主题：右下肺炎症影
必须出现：右下肺区域、局部炎症阴影、肺部轮廓
不能出现：真实患者信息、医院标识、文字标签、夸张病变、多处不相关病灶
风格：医学教材示意图，清晰，简洁，非照片
题目考点：肺炎影像表现识别
审核重点：病变位置是否正确，是否与题干一致
```

### 07 质量控制

基础评估维度：

- 题干是否完整。
- 选项数量是否合规。
- 答案是否存在于选项。
- 是否符合 A2 型题特征。
- 是否存在多个正确答案风险。
- 配图是否已通过审核。

不把“是否包含解析”“是否包含来源”作为首期必检项。

### 08 人工审核流程

系统支持多轮审核，审核轮数和每轮审核人由后台配置。

功能包括：

- 配置专家库。
- 配置审核流程。
- 配置审核轮数。
- 配置每一轮审核人或专家组。
- 记录每轮审核意见。
- 记录修改内容。
- 支持通过、驳回、退回修改。

标准：

- 只有专家通过的题目才能进入正式题库。
- 所有修改和审核都应留痕。
- 带图题必须同时审核题目和图片。

### 09 专家库

专家库字段建议：

- 专家 ID。
- 姓名。
- 所属专业或科室。
- 擅长知识点。
- 可审核题型。
- 是否启用。

专家库用于审核流程配置。

### 10 题库管理

功能包括：

- 按专业、知识点、难度、状态查询。
- 按关键词搜索。
- 查看审核状态。
- 查看配图状态。
- 导出审核通过的题目。

不按来源查询，因为首期不要求试题来源。

### 11 Web 管理端

导航与出题入口：

- 左侧使用五个可折叠业务分类：基础数据、命题管理、审核管理、题库与统计、系统管理。分类之间有清晰分隔，深色侧栏沿用系统蓝色，主内容区保持原有颜色。
- 子菜单按权限显示，无可访问内容的分类隐藏。当前页面所在分类自动展开，支持键盘操作与移动端抽屉导航。
- 批量推理不再作为独立侧栏条目；从单题出题页右上角进入批量子页面，右上角可返回单题出题。
- 单题与批量页面切换保留本次编辑内容和配置。批量页隐藏或离开时停止轮询，返回批量页恢复当前任务状态查询。
- 旧 `/batch` 地址兼容跳转到 `/generate/batch`；单题与批量权限分别校验，仅有批量权限的账号仍可进入命题工作区。

首期页面包括：

- 知识点 Excel 导入页。
- AI 出题页。
- 多模态配图生成页。
- 专家库管理页。
- 审核流程配置页。
- 题目审核页。
- 题库查询与导出页。

## 5. 非功能需求

### 5.1 性能

- 单题生成目标小于 1 分钟。
- 批量生成应支持任务队列。
- 查询题库应支持分页。

### 5.2 稳定性

- 外部模型调用失败时应返回明确错误。
- 批量任务失败时应保留已成功结果。

### 5.3 安全

- API Key 不得写入代码仓库。
- 权限应按角色控制。
- 未通过审核的题目不能进入正式题库。

### 5.4 可扩展

- 千问文本生成、生图模型、数据库、审核流程应保持可替换。
- 当前不做知识图谱，但代码结构不要阻碍后续扩展。

## 6. 技术栈方案

### 6.1 后端语言

- Go + Python 双栈。
- Go 负责主服务、接口、审核流程和数据管理。
- Python 可用于后续算法实验或生图服务封装。

### 6.2 大模型调用

- 文本出题：阿里云百炼千问 OpenAI 兼容接口。
- 当前直接使用千问生成题目，不接知识图谱。

### 6.3 AI 生图

- 接入外部生图模型。
- 系统负责生成结构化提示词。
- 系统保存候选图、提示词和审核状态。
- 专家选择可用图。

### 6.4 数据库

- 原型可先用 SQLite 或文件存储。
- 正式版优先 PostgreSQL。

### 6.5 前端

- Vue 3 + Vite + Element Plus。

## 7. 首期验收标准

- 能批量导入知识点 Excel。
- 能按知识点搜索和选择。
- 能调用千问生成 A2 文本题。
- 能为题目生成 3-5 张 AI 候选配图。
- 能记录生图提示词和候选图。
- 能配置专家库。
- 能配置审核轮数和每轮审核人。
- 能记录每轮审核意见。
- 带图题必须图片和题目均审核通过后才能入库。
- 能查询并导出审核通过的题目。
