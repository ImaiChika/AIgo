## 1. 项目目的

构建一套面向国家执业医师考试 A2 型试题的 AI 智能命题系统，实现“知识点导入、AI 出题、质量初评、多轮专家审核、题库入库”的基本流程。

当前版本以直接调用千问大模型出题为主，不引入知识图谱，不强制使用历史真题，不把解析和试题来源作为首期必填内容。

大致流程：

```text
知识点 Excel / CSV / Word 表格
        ↓
千问生成 A2 试题草稿
        ↓
基础质量初评
        ↓
多轮专家审核（后台配置审核几轮、每轮谁审核）
        ↓
修改、通过、驳回或重新生成
        ↓
正式题库
```

树状图梳理：

```text
智能命题系统
├─ 1. 基础数据
│  ├─ 年度大纲版本管理与批量文档导入
│  └─ 知识点目录树、搜索与单条增删改
│
├─ 2. AI 出题
│  ├─ A2 文本试题生成
│  ├─ 批量生成
│  └─ 干扰项生成
│
├─ 3. 质量控制
│  ├─ 基础格式校验
│  └─ 答案唯一性校验
│
├─ 4. 多轮审核
│  ├─ 专家库
│  ├─ 审核流程配置
│  ├─ 每轮审核人配置
│  ├─ 审核意见与修改记录
│  └─ 最终入库
│
├─ 5. 题库管理
│  ├─ 题目查询
│  ├─ 状态管理
│  └─ 导出
│
└─ 6. 后续可选
   └─ 历史真题参考加载（如后续需要）
```

## 2. 项目范围

### 2.1 当前优先开发范围

- Go/Python 后端框架。
- 千问大模型 API 调用封装。
- A2 型试题格式生成。
- 年度大纲版本隔离、批量文档导入。
- 知识点目录树、搜索与单条增删改。
- 文本试题生成。
- 基础质量校验。
- 专家库。
- 可配置多轮审核。
- 题库查询与导出。

### 2.2 当前暂不考虑

- 知识图谱。
- Neo4j。
- 复杂来源资料管理。
- 历史真题强依赖。
- 解析和试题来源必填。
- 题目附带图片、多模态素材、AI 生图及图片审核。
- IRT、Bloom、强化学习等研究模块。

### 2.3 历史真题的处理原则

当前不需要考虑历史真题。

如果后续确实要使用历史真题，不做复杂题库知识图谱，只做成类似 agent 的参考加载方式：

```text
用户选择知识点
        ↓
系统检索少量相关历史真题或样例
        ↓
把这些样例加载到提示词上下文
        ↓
千问参考样例生成新题
```

历史真题只作为提示词参考，不作为当前核心功能。

## 3. 用户角色

### 3.1 超级管理员

- 系统唯一的最高权限账号。
- 管理用户、角色和权限，并向管理员下放业务权限。
- 默认拥有单题出题与批量推理权限；批量推理可由超级管理员在权限分配处按需授予其他账号。
- 配置千问 API、数据库等参数。
- 配置专家库。
- 配置审核流程、审核轮数和每轮审核人。

### 3.2 管理员

- 由超级管理员分配和调整权限。
- 按授权范围管理用户、专家、题库、知识点和审核流程。
- 可以安排审核、参与专家审核和最终决断，但不能管理角色模板或创建第二个超级管理员。
- 默认仅继承单题出题权限，不默认继承批量推理权限；是否开放批量推理由超级管理员单独调整。

### 3.3 命题教师或医学专家

- 选择专业、知识点、难度和生成数量。
- 查看 AI 生成试题。
- 使用本人独立的正式、待审核、淘汰三层个人题库。
- 修改题干、选项和答案。
- 通过「待我修改」处理退回本人修订的题目，并可将个人正式题申请分享至全局库。
- 填写审核意见。
- 决定通过、驳回或要求修改。
- 医学专家默认不查看全局题库、审核记录汇总和数据统计，也不管理知识点；仍可读取知识点并处理分配给自己的审核任务。
- 单题出题与批量推理是两个独立权限。命题教师/医学专家默认仅可单题出题，未分配批量推理权限时不能查看、提交或导入批量任务。

## 4. 功能需求

### 01 试题领域模型

系统应定义统一的 A2 型试题结构。

首期核心字段：

- 题目 ID。
- 临床情境题干。
- 选项列表。
- 正确答案。
- 关联知识点。
- 难度等级。
- 创建时间。
- 审核状态。
- 版本记录。

可选字段：

- 答案解析。
- 试题来源。

说明：

- 解析和试题来源首期不作为必填项。
- 后续如果老师要求再补充解析和来源，可作为扩展字段启用。

标准：

- 题目必须具备题干、选项和答案。
- A2 单选题默认支持 A-E 五个选项，必要时可兼容四选项。
- 答案必须存在于选项中。

### 02 知识点管理

以年度考试大纲为管理单位，每个版本包含一整套独立的知识点。

- 支持按考试年份新建大纲版本，填写名称和说明。新版本先整理，导入完成后启用。
- 默认展示考试年份最新的已启用版本；历史版本仍可查询和出题。
- 左上角展示当前版本名称；右侧入口打开独立版本窗口，展示年份、名称、状态和知识点数量，支持搜索与状态筛选，确认选择后切换。
- 允许删除整套大纲版本及其知识点，删除前展示影响范围。历史题目、审核记录、已提交任务快照保留。
- 删除默认版本后回退到剩余年份最新的已启用版本；没有已启用版本时显示空状态，不自动启用整理中的版本。
- 删除最后一个版本后仍可新建大纲；出题页与批量页在版本失效时清除旧选择。
- 不同版本的大纲代码可以相同，知识点 ID 必须跨版本唯一，修改和导入不能覆盖其他年度。
- 支持 Excel（.xlsx）、UTF-8 CSV、Word（.docx 普通表格）多文件批量导入。
- 导入支持追加/更新和替换当前版本整套大纲；所有文件校验通过后在一个事务中写入。
- 支持单个知识点新增、编辑、删除；同版本大纲代码唯一，编辑需要检查修订号，防止互相覆盖。
- 左侧目录树按“分类 → 专业/系统 → 单元 → 细目”逐级展开，右侧展示所选目录及全部下级的知识点。
- 关键词搜索、目录过滤及分页均限定在当前版本；出题选择器保留现有布局，增加版本选择。
- 单题和批量出题记录实际知识点 ID、版本及内容快照；修改/删除知识点不能改写已有题目。
- 批量“跳过已有题目”按版本与大纲代码判断，任务结果使用提交时的知识点快照。
- 新增、修改、删除、导入及启用操作要求 knowledge:manage 权限，并记录审计日志。

不做知识图谱关系维护，也不扩展知识点与指南、教材、文献的复杂关联。

### 03 AI 文本试题生成

根据结构化请求调用千问大模型生成 A2 型试题。

输入参数：

- 专业或科目。
- 难度。
- 知识点。
- 生成数量。
- 可选临床场景。

输出内容：

- 临床情境题干。
- A-E 选项。
- 正确答案。
- 难度。
- 关联知识点。

可选输出：

- 解析。
- 试题来源。

标准：

- 输出尽量使用严格 JSON。
- AI 生成结果默认为草稿，不能直接进入正式题库。
- 每次生成应记录模型名称、提示词和生成时间。
- 单题出题使用独立的 `question:generate` 权限；批量推理使用独立的 `batch:run` 权限，二者分别校验、分别分配。

### 04 批量生成

功能包括：

- 根据同一知识点批量生成多道题。
- 批量生成失败时不影响已成功生成的题目。
- 每次批量任务记录模型、提示词和生成数量。
- 批量推理默认仅超级管理员可用；普通管理员、命题教师和医学专家默认不分配 `batch:run`，如需使用由超级管理员在权限矩阵中单独授予。

### 05 干扰项生成

功能包括：

- 围绕相近疾病、症状、检查、治疗方案生成干扰项。
- 避免明显错误或过于简单的选项。
- 避免多个正确答案。

当前不使用知识图谱或混淆网络，先由千问结合提示词直接生成。

### 06 质量控制

基础评估维度：

- 题干是否完整。
- 选项数量是否合规。
- 答案是否存在于选项。
- 是否符合 A2 型题特征。
- 是否存在多个正确答案风险。

不把“是否包含解析”“是否包含来源”作为首期必检项。

AI 质量检查只对医学内容准确性、选项逻辑、答案唯一性、解析准确性和 A2 格式做通过/不通过判断。
难度、认知层次、考核要点、大纲代码、专业和系统等命题元数据不作为自动淘汰条件；发现元数据不一致时只记录为信息提示，
用于修正出题提示词或人工审核，不得让核心内容和格式合格的题目进入淘汰流程。

### 07 人工审核流程

系统支持多轮审核，审核轮数和每轮审核人由后台配置。

功能包括：

- 配置专家库。
- 配置审核流程。
- 配置审核轮数。
- 配置每一轮审核人或专家组。
- 记录每轮审核意见。
- 记录修改内容。
- 支持通过、驳回、退回修改。

标准：

- 只有专家通过的题目才能进入正式题库。
- 所有修改和审核都应留痕。

### 08 专家库

专家库字段建议：

- 专家 ID。
- 姓名。
- 所属专业或科室。
- 擅长知识点。
- 可审核题型。
- 是否启用。

专家库用于审核流程配置。

### 09 题库管理

功能包括：

- 按专业、知识点、难度、状态查询。
- 按关键词搜索。
- 查看审核状态。
- 导出审核通过的题目。

不按来源查询，因为首期不要求试题来源。

题库采用“生命周期分层 + 分类子题库”二轴模型，不建设三套物理数据库：

- 正式题库、待审核题库、淘汰题库是由题目状态唯一推导的三个逻辑视图；题目状态是唯一事实来源。
- 分类子题库（如内科、外科、呼吸）是待审核层的组织、权限范围和批量送审单位，不是第四种生命周期状态。
- 题目发布或驳回后保留提交时的分类快照用于历史追溯，但正式/淘汰题不能再调整分类子题库。
- 每次送审必须明确一个分类子题库并把 submission_bank_id 固化到审核任务；多轮审核始终按该快照路由，不能读取题目后来变化的分类。
- 通用审核流程可以复用于多个分类子题库，但每次批量送审仍必须显式选择一个分类子题库，禁止“空值代表全部”造成误提交。
- 已被正式题、淘汰题、审核流程或历史审核任务引用的分类子题库不得物理删除。

个人题库与全局题库：

- 每个用户拥有独立的正式、待审核、淘汰三层个人题库；AI 单题/批量生成的题目按用户归属进入个人题库。
- 个人正式题目可以申请分享至全局题库；一题只能申请一次。
- 个人正式题库支持勾选多题分享，以及按当前专业、分类子题库、关键词筛选结果批量分享（包含跨分页结果，每批最多 500 题）。提交前确认题目数量与筛选范围，确认后只提交该批次已选定的题目；已申请、被撤回或已删除的题目自动跳过。原题及审核记录保留，分享仍需管理员审批。
- 分享申请状态 `pending` 进入全局待审核库，由具备分享审批权限的管理员处理；审批 `approved` 后进入全局正式库，`rejected` 进入全局淘汰库。
- 全局题库默认不向客户开放；管理员按 `question:view_global` 查看，题目详情不展示出题人，但审计日志和版本记录保留出题人用于追溯。

权限与任务可见性：

- 系统管理员默认拥有全部权限，包括审核、最终决断、正式题库查看、撤回、导出和删除。
- 命题教师默认只浏览其分类范围内的待审核题库，并通过「待我修改」处理本人被退回的题目。
- 医学专家既是个人题库用户也是审核人：可生成题目、浏览本人三层题库、处理「待我修改」、申请分享，并通过「待我审核」处理分配任务。
- 医学专家默认不具备全局题库、审核记录汇总、数据统计和知识点管理权限；知识点保持只读。
- 最终把关人由管理员授予 review:final，并通过「待我决断」中的任务/把关人名单查看和决断题目；无需取得题库浏览权限。
- 正式题库、待审核题库、淘汰题库查看权限彼此独立，所有列表、详情、审核记录和统计均不得形成旁路。
- 审核记录汇总使用独立的 review:view_results 权限，不能由个人题库查看权限旁路获得。
- 审核记录页面默认展示“我的题库”，有全局查看权限者可切换到“全局题库”；统计与列表使用同一明确范围，不因管理员拥有全局权限而自动隐藏本人审核记录。
- 用户的分类子题库范围同时约束角色继承权限和直接权限；角色回答“能做什么”，分类范围回答“可在哪些子题库做”。
- 审核记录和统计只汇总调用者有权查看的生命周期分层与分类范围。

统一搜索规则：

- 题目关键词统一覆盖题干、选项、答案、解析、考核要点、专业、系统、知识点快照、大纲代码、来源和题目 ID；各页面不得自行维护不同字段清单。
- 空格、中文/英文逗号和分号可分隔多个关键词，多个关键词按 AND 关系匹配；`%`、`_` 等数据库通配符按普通字符处理。
- 分类子题库“手动添加”搜索只返回尚可调整分类的待审核题，但已经位于当前子题库的命中项仍须展示，并明确标记“已在本库”，不能静默隐藏。
- 手动添加页的状态、难度等筛选必须在后端分页前执行，禁止前端分页后再剔除导致总数、页数和结果不一致。
- 难度筛选同时兼容数值系数与历史文本值：简单 ≤0.60，中等 0.61–0.80，困难 >0.80。
- 搜索请求须防止旧请求晚返回覆盖新请求；搜索为空时允许分页浏览当前权限范围内的全部候选。

### 10 Web 管理端

导航与出题入口：

- 左侧使用五个可折叠业务分类：基础数据、命题管理、审核管理、题库与统计、系统管理。分类之间有清晰分隔，深色侧栏沿用系统蓝色，主内容区保持原有颜色。
- 子菜单按权限显示，无可访问内容的分类隐藏。当前页面所在分类自动展开，支持键盘操作与移动端抽屉导航。
- 批量推理不再作为独立侧栏条目；从单题出题页右上角进入批量子页面，右上角可返回单题出题。
- 单题与批量页面切换保留本次编辑内容和配置。批量页隐藏或离开时停止轮询，返回批量页恢复当前任务状态查询。
- 旧 `/batch` 地址兼容跳转到 `/generate/batch`；单题与批量权限分别校验，仅有批量权限的账号仍可进入命题工作区。
- 未分配批量推理权限的账号不显示批量入口；直接访问批量地址时回到单题出题页并提示联系超级管理员，不展示批量任务内容。既没有单题也没有批量权限时回到知识点页。

首期页面包括：

- 年度大纲知识点管理页（版本、目录树、批量导入、单条增删改）。
- AI 出题页。
- 专家库管理页。
- 审核流程配置页。
- 题目审核页。
- 题库查询与导出页。
- 我的个人题库页、全局题库页和全局题库分享申请/审批页。

## 5. 非功能需求

### 5.1 性能

- 单题生成目标小于 1 分钟。
- 批量生成应支持任务队列。
- 查询题库应支持分页。

### 5.2 稳定性

- 外部模型调用失败时应返回明确错误。
- 批量任务失败时应保留已成功结果。

### 5.3 安全

- API Key 不得写入代码仓库。
- 权限应按角色控制。
- 未通过审核的题目不能进入正式题库。

### 5.4 可扩展

- 千问文本生成、数据库、审核流程应保持可替换。
- 当前不做知识图谱，但代码结构不要阻碍后续扩展。

## 6. 技术栈方案

### 6.1 后端语言

- Go + Python 双栈。
- Go 负责主服务、接口、审核流程和数据管理。
- Python 可用于后续算法实验。

### 6.2 大模型调用

- 文本出题：阿里云百炼千问 OpenAI 兼容接口。
- 当前直接使用千问生成题目，不接知识图谱。

### 6.3 数据库

- 原型可先用 SQLite 或文件存储。
- 正式版优先 PostgreSQL。

### 6.4 前端

- Vue 3 + Vite + Element Plus。

## 7. 首期验收标准

- 能批量导入 Excel、CSV、Word 表格，或单条增删改知识点。
- 不同年度大纲隔离，默认最新已启用版本，历史版本可出题。
- 能按目录树、关键词搜索和选择知识点，搜索分页保持版本范围。
- 大纲修改或删除后，旧题和批量任务知识点快照保持不变。
- 能调用千问生成 A2 文本题。
- 能配置专家库。
- 能配置审核轮数和每轮审核人。
- 能记录每轮审核意见。
- 能查询并导出审核通过的题目。
