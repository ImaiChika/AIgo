二、部署事故记录（已修复，重点防再犯）
================================================================================

事故：rsync 源码到服务器时把 Mac 侧 deploy/secrets/（数据库口令、JWT_SECRET）
      一并覆盖了服务器原值，migrate/app 无法启动。
处置：用容器内 local trust 把数据库角色口令重置为当前密钥文件值；旧 JWT_SECRET
      加密的 AI 服务配置行无法解密，删除后由启动引导重建，API Key 通过 AI 服务
      配置页重新录入并用真实生成验证。
后果：全部账号需重新登录一次（JWT 密钥变更的正常结果）。
预防：①rsync 同步代码时务必排除 deploy/secrets/（大修改指引第 9 条已警示）；
      ②正式密钥以服务器 /opt/aigo/deploy/secrets/ 为唯一权威源，Mac 侧副本
      不可反向覆盖。

四、CI 说明（重要）
================================================================================

GitHub Actions（.github/workflows/ci.yml）的 go test 在 service 容器里带
AIGO_TEST_POSTGRES_DSN 跑真实 PostgreSQL 集成测试；本地不设该变量时这些测试
会被 SKIP——这次 stats 口径变更漏改集成断言就是被本地跳过掩盖的。
本地复刻 CI 全量验证的方法：
  createdb aigo_test（如无）
  AIGO_TEST_POSTGRES_DSN="postgres://postgres:postgres@localhost:5432/aigo_test?sslmode=disable" \
    go test -count=1 ./...
  go test -count=1 -race ./internal/storage/... ./internal/aicheck/ ./internal/review/
  govulncheck ./...（可达漏洞必须为 0）
以后凡是改了统计/分层/全局口径，必须带 DSN 跑一遍再推。

五、搁置项：P1-4 空角色旧 token 的权限并集（待决断）
================================================================================

风险：注册后"未分配角色"期间签发的 token（24 小时有效）里 role 为空；管理员
随后给该账号挂上双身份后，旧 token 在过期前每次请求都拿"全部已挂身份+直授
权限"的并集，可在同一会话里既出题又审题，绕过互斥。
边界：触发条件较苛刻（token 签发时账号必须一个角色都没有）；本次 P1-3 修复
未扩大该口子（业务接口仍按当前身份逐请求校验）。
候选修法（二选一，都是小改动）：
  A. requireAuth 对"token 无角色但账号已有挂载角色"的请求直接 401，要求重登；
  B. HasPermission 在上下文角色为空且用户存在挂载角色时拒绝（fail-closed）。
等确认后执行，改完需带 AIGO_TEST_POSTGRES_DSN 跑全量。

P2 级：
1. 互斥的服务端零强制：管理员可给审题老师直授 question:generate，超管可创建
   同时含出题+审题权限的自定义角色（auth.go effectivePermissionsForRole 把
   直授权限并入每个身份；SaveRoleAs 不校验互斥）。用户管理页文案已提示风险，
   但服务端不设防。
2. 归档流程+审核人失效的重送死角：退修题的原流程已删（归档不可改不可重建）、
   原审核人又被收回审题权限时，重送永远 409"请先更新审核流程"，题目卡死在
   「待我修改」（review/service.go submitQuestionLocked 的 resolveReviewers）。
   可选出路：允许把关人把该任务迁移到新流程，或重送校验失败时允许把关人直接
   终态决断。
3. /api/auth/me 无人在前端调用：权限/角色只在登录时写 localStorage，管理员
   在线授权/收权对方无感（auth.js；路由守卫信任陈旧数据）。
4. 多标签页身份不同步：A 页签切身份后 B 页签请求静默换 token 吃 403，无
   storage 事件广播（auth.js setAuth）。
5. 生成页侧栏"个人题库/待审核 N"计数不随 AI 检查淘汰刷新，需重进页面。
6. 批量页无等待计时（指引第 4 条要求有）；单题循环无失败重试（一次网络抖动
   永久损失一个生成项）；无并发上限（可同时提交 N 个任务；重启 resumePending
   最多并行拉起 200 个）。
7. "我已出题"是现存题数口径：AI 检查淘汰（物理删除）会扣减，不是累计
   （handler_auth.go handleMySummary generated=存活题计数）。
8. AI 质量检查"通过率"分母不含淘汰档案，显示 100% 与同屏"淘汰 N"矛盾
   （verdicts 只记 pass）。
9. handleMySummary 的 reviewed 是 ListAllTasks+逐任务 ListRecords 的 N+1
   全表内存遍历，侧栏角标与我的数据页每次加载都触发（建议聚合 SQL）。
